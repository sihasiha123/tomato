# demo/4-5 目录说明

这份文档说明当前目录下各文件的用途，并重点整理 `Flag*.py` 系列脚本的差异。当前目录是一套轨道遍历现场调试脚本，不是独立 Python 包；脚本通常直接在 ROS 1、FAST-LIVO、SocketCAN `can0`、相机和 YOLO 环境都启动后运行。

## 一、Flag 系列差异

| 文件 | 定位 | 触发方式 | 前进控制 | 回零控制 | 横移/姿态 | 适合场景 |
| --- | --- | --- | --- | --- | --- | --- |
| `Flag.py` | 最初版本、基线脚本 | 等待 `/flag1 == 1` | 主要依赖四轮 CAN 里程计 `0x25`，默认前进距离较短 | 轮式里程计回零，失败时有时间兜底 | 回零后按轮次横移，无 FAST 姿态回正 | 只作为老版本参考，不建议新流程优先使用 |
| `Flag_4_2.py` | 当前上轨/下轨基础版本，也是其他控制器父类 | 等待 `/flag1 == 1` | 使用 FAST-LIVO `/aft_mapped_to_init` 位姿做距离闭环，支持前进分段与采摘 CAN 交互 | FAST 位姿主闭环回零；代码保留部分轮里程函数，但运行主线已禁用轮里程回退 | 下轨后按 FAST yaw 回到基准角，再按配置横移 | 单轨上轨/下轨、作为 `traverse.py` 底层动作模块 |
| `Flag_4_16.py` | 基于 `Flag_4_2.py` 的定点停车版本 | 等待 `/flag1 == 1` | 只替换前进阶段：支持首次距离、后续步进距离、累计 X 目标列表；每段停车后继续采摘 CAN 交互 | 继承 `Flag_4_2.py` 的 FAST 回零 | 继承 `Flag_4_2.py` 的姿态回正和横移 | 需要在固定采摘点/工作点停车时使用 |
| `Flag_4_2_return_test.py` | 从 `Flag_4_2.py` 抽出的单独测试脚本 | 默认启动后自动跑一轮，不等 `/flag1` | 前进到工作点、分段停车，可等待或跳过采摘完成 | 继承 `Flag_4_2.py` 的 FAST 回零 | 默认不做横移，不做姿态恢复；可用参数打开姿态恢复 | 夜间/离线测试“入轨 + 分段工作 + 回零” |

### 1. `Flag.py`

- 最初的上轨往返状态机。
- 主要依赖四轮里程计 CAN 上报，帧 ID 默认 `{1,2,3,4}`，数据首字节 `0x25`。
- 默认流程是：等待 `/flag1`，切行驶模式，上轨，倒车回零，必要时横移，发布 `/rail_cycle_done`。
- 没有 FAST-LIVO 位姿闭环，也没有下轨后姿态回正逻辑。
- 适合看老逻辑和 CAN 协议，不建议作为当前主流程入口。

### 2. `Flag_4_2.py`

- 当前最重要的基础控制脚本。
- 新增 FAST-LIVO 位姿订阅，默认话题是 `/aft_mapped_to_init`。
- 前进、回零、姿态恢复都围绕 FAST 位姿/yaw 展开。
- 增加采摘状态 CAN：
  - `0x20`：向采摘端发 busy/ready。
  - `0x21`：等待采摘端 done。
- 增加下轨后的姿态恢复：回到首次/导航成功时记录的 FAST yaw 基准角。
- 支持横移次数和横移距离列表，通常来自 `/rail_workflow/lateral_move_count` 和 `/rail_workflow/lateral_distances_mm`。
- `traverse.py`、`Flag_4_16.py`、`Flag_4_2_return_test.py` 都继承它。

### 3. `Flag_4_16.py`

- 不复制整套底层逻辑，而是继承 `Flag_4_2.UpRailFlagController`。
- 主要改动集中在前进阶段：
  - `~forward_first_segment_mm`：第一次前进距离。
  - `~forward_segment_mm`：后续每段距离。
  - `~forward_target_x_offsets_m` / `~forward_target_x_list`：可按 FAST 累计 X 目标停车。
  - `~force_drive_mode_before_forward`：每次前进前补发自动/行驶模式。
- 回零、姿态回正、横移和完成信号沿用 `Flag_4_2.py`。
- 比 `Flag_4_2.py` 更适合“每隔固定距离停一下”的工作点流程。

### 4. `Flag_4_2_return_test.py`

- 也是继承 `Flag_4_2.UpRailFlagController`，但入口变成测试模式。
- 默认 `~auto_start:=true`，启动后自动执行一轮，不需要视觉节点发 `/flag1`。
- 默认测试参数：
  - 工作区入口距离 `~work_area_entry_distance_mm` 默认 `200 mm`。
  - 工作步进 `~work_step_mm` 默认 `200 mm`。
  - 总距离 `~work_total_distance_mm` 默认 `10000 mm`。
- 默认不横移、不恢复姿态；如需姿态恢复可设 `~run_angle_restore:=true`。
- 可设 `~skip_harvest_wait:=true` 跳过等待 `0x21` 采摘完成。

## 二、当前推荐组合

### 完整遍历流程

常用组合是：

```bash
python3 traverse.py
python3 new_copy_no_capture.py
```

整体逻辑：

1. 外部导航到轨道入口。
2. `traverse.py` 等 `/cur_global_goal_status` 进入成功状态。
3. `traverse.py` 放开 `/traverse/alignment_enabled`。
4. `new_copy_no_capture.py` 开始视觉对轨。
5. 对轨完成后视觉节点发布 `/flag1 == 1`。
6. `traverse.py` 继承 `Flag_4_2.py` 的动作，执行上轨、下轨、姿态恢复、横移。
7. 发布 `/rail_cycle_done`，进入下一轮。

不用真导航做联调时，可用：

```bash
python3 send_fake_nav_success.py --once --repeat 8 --yaw-deg 0
```

### 单独测试上轨/回零

```bash
python3 Flag_4_2_return_test.py
```

用于不启动视觉和遍历时，只验证上轨、工作点停车、采摘 CAN、FAST 回零。

## 四、traverse 版本关系

`demo/4-5/` 本身就有自己的 `traverse.py`，这是当前目录里的遍历总控脚本。除此之外，同级目录里还有两套 4-23 相关版本：

| 位置 | 定位 | 主要特点 |
| --- | --- | --- |
| `/home/ubuntu/mmLaneDet-master/demo/4-5/traverse.py` | 4-5 当前目录自带版本 | 继承 `Flag_4_2.py`；支持等待外部导航成功，也保留主动发布导航点、`nav_ready` 兼容、首次对轨 x 回退兜底等旧分支；上轨可按 `forward_distances_mm` 距离表直行；下轨可按下一条轨道 x 修正回退目标。 |
| `/home/ubuntu/mmLaneDet-master/demo/4-23/traverse.py` | 4-23 完整状态机版 | 在 4-5 版本基础上加了显式流程状态机，如 `WAIT_NAV`、`PREPARE_ALIGNMENT`、`WAIT_ALIGNMENT`、`RUN_SEQUENCE`、`ADVANCE`；还支持用轨道实测表自动计算横移距离。 |
| `/home/ubuntu/mmLaneDet-master/demo/4-23-lite/traverse.py` | 4-23 精简版 | 只保留现场实际用的链路：等外部导航成功、开放对轨、收到 `/flag1` 后执行上/下轨、下轨后回角和横移；移除了主动发导航点、`nav_ready`、多导航点遍历、首次对轨 x 回退等分支。 |

对应配置：

| 配置文件 | 说明 |
| --- | --- |
| `demo/4-5/traverse.yaml` | 4-5 当前配置，16 轮，从 16 号轨到 1 号轨；`restore_heading_before_alignment: false`，导航到位后直接对轨；横移主要用 `lateral_distances_mm` 表。 |
| `demo/4-5/Log/traverse.yaml` | 4-5 目录里保留的旧配置备份，和当前配置最关键差异是 `restore_heading_before_alignment: true`，即导航到位后先回角再开放对轨。 |

## 六、YAML 配置区别

### `traverse.yaml`

- 当前多轨遍历主配置。
- 默认 `cycle_count: 16`，轨道顺序是 `16 -> 15 -> ... -> 1`。
- 使用 `/cur_global_goal_status` 作为导航成功话题。
- `use_alignment_gate: true`，由 `traverse.py` 控制视觉对轨开关。
- `forward_distances_mm` 配置每轮上轨前进距离。
- `rail_reference_points` 保存每条轨道在 FAST 坐标系下的 `x_m/y_m`。
- `lateral_distances_mm` 保存每轮下轨后的横移距离。

### `rail_workflow.yaml`

- 更早的简单配置。
- 默认 `cycle_count: 2`。
- 还保留了旧的导航目标列表字段 `navigation_goals`。
- 适合单独跑 `Flag_4_2.py` 或回看旧联动方式，不是当前完整遍历的首选。

## 七、关键 ROS 话题和 CAN 约定

| 名称 | 类型/协议 | 作用 |
| --- | --- | --- |
| `/flag1` | `std_msgs/Int32` | 视觉对轨完成后发 `1`，触发上轨动作。 |
| `/rail_cycle_done` | `std_msgs/Int32` | 上轨/下轨/横移一轮完成信号，成功通常发正轮次，失败发负轮次。 |
| `/aft_mapped_to_init` | `nav_msgs/Odometry` | FAST-LIVO 位姿来源，用于距离闭环和 yaw 姿态回正。 |
| `/traverse/alignment_enabled` | `std_msgs/Int32` | `traverse.py` 发给视觉节点的对轨门控。 |
| `/cur_global_goal_status` | `rover_msgs/roverGoalStatus` | 当前配置使用的导航成功状态话题。 |
| CAN `0x00A` | 底盘控制器 ID | 速度、模式、横移、角度等底盘控制命令默认发往这个 ID。 |
| CAN `0x20` | 采摘状态 | 控制端向采摘端发 busy/ready。 |
| CAN `0x21` | 采摘完成 | 采摘端向控制端回 done。 |

底盘模式默认值：

- `0x02`：行驶/自动模式。
- `0x03`：角度模式。
- `0x04`：横移/等待模式。

## 八、注意事项

- 当前正式遍历优先看 `traverse.py + traverse.yaml + new_copy_no_capture.py + Flag_4_2.py`。
- 不要把 `rail_workflow.yaml` 和 `traverse.yaml` 混成一个配置；两者服务的流程不一样。
- 如果要复现 4-23 的 traverse 行为，重点看 `Log/traverse.yaml`，尤其是 `restore_heading_before_alignment: true`。
- `traverse.yaml` 当前明确使用 `/cur_global_goal_status`，不要误换成 `/cur_local_goal_status`，否则可能在导航中间点提前开放对轨。
- `traverse.yaml` 中 `lateral_distances_mm` 应与实际横移次数匹配；多轨遍历时通常需要 `cycle_count - 1` 个横移距离。
- `Log/` 下是历史运行产物，里面的旧脚本不要当作当前主版本修改。
- 修改运动参数时优先改 YAML 或 ROS 参数，不要直接改 Python 默认值，除非确实要改变程序逻辑。
