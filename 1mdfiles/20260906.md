# PUTN 与 4-5 代码关系说明

日期：2026-09-06

## 一、先说结论

`putn_ws/src/putn-main` 基本可以确认是从外部开源项目 PUTN 获取后，再放进当前小车工程中进行适配的。

证据来自 [PUTN 原始说明](../putn_ws/src/putn-main/README.md)：

- 项目全名是 **PUTN: A Plane-fitting based Uneven Terrain Navigation Framework**。
- README 给出了对应的 IROS 论文和原作者信息。
- 安装步骤明确写着：`git clone https://github.com/jianzhuozhuTHU/putn.git`。
- [LICENSE](../putn_ws/src/putn-main/LICENSE) 使用 GPLv3 许可证。
- 原项目面向室外非结构化、起伏地形中的通用 UGV 导航，并不是专门为农业轨道或番茄采摘开发的。

但是，当前目录中已经没有 `putn-main/.git`，`4-5` 中也没有独立的 `.git`。只有整个 `5-9` 根目录是 Git 仓库。因此现在不应把它们理解成两个独立仓库，而应理解成：

```text
当前总工程
├── putn_ws/src/putn-main/   引入并适配的通用导航算法
└── 4-5/                    针对当前小车和轨道任务编写的应用代码
```

无法仅凭当前文件确定 PUTN 对应的上游提交版本，也无法完整区分每一处上游代码和后续修改，因为原来的 Git 提交记录没有保留下来。

## 二、PUTN 原项目是什么

PUTN 是一套 ROS 地面机器人导航框架，解决的是：

> 已知小车当前位置、目标点和三维点云地图，怎样规划一条可行路径，并控制小车走到目标点。

原 README 将算法分为三个部分：

1. 全局规划：PF-RRT*。
2. 地形建模：GPR，高斯过程回归。
3. 局部规划与跟踪：NMPC，非线性模型预测控制。

原项目使用 Ubuntu 16.04/18.04、ROS、A-LOAM、Scout 2.0 小车和 Ouster OS0-128 激光雷达。原始控制输出是 ROS 的 `geometry_msgs/Twist`，也就是常见的 `/cmd_vel` 速度指令。

PUTN 本身不包含以下轨道业务：

- YOLO 轨道识别；
- 左右轨道直线拟合和中线计算；
- 根据像素误差横移对轨；
- CAN 上轨道、下轨道和轨道间横移；
- 农业采摘循环。

## 三、`putn_ws` 这一层怎样理解

`putn_ws` 是 ROS Catkin 工作空间，不是某一个算法模块的名字：

```text
putn_ws/                       Catkin 工作空间
└── src/                       Catkin 源码目录
    └── putn-main/             引入的 PUTN 项目副本
        └── src/
            ├── putn/          导航算法相关 ROS 功能包
            └── scout_simulator/  Scout/Gazebo 仿真
```

当前工程中值得关注的 PUTN 模块如下：

| 模块 | 作用 |
|---|---|
| `putn_launch` | 启动导航节点、加载参数和 RViz 配置 |
| `putn_waypoint_generator` | 接收 `/cur_goal`，生成规划航点 |
| `putn_planning` | 建立点云体素地图，执行 PF-RRT* 全局规划 |
| `putn_gpr` | 对局部地形进行平面/高程预测 |
| `putn_mpc` | 生成局部轨迹，并通过 `/cmd_vel` 控制小车跟踪 |
| `rover_msgs` | 导航状态等自定义 ROS 消息 |
| `putn_rviz_plugins` | RViz 目标点与可视化工具 |
| `putn_map`、`scout_simulator` | Gazebo 地图和车辆仿真，不是当前轨道主流程 |

当前 PUTN 代码明显已经被接入实际工程，例如使用工程自己的 PCD 地图、目标话题和导航完成状态。但它的核心职责仍然是通用导航。

## 四、`4-5` 是什么

`4-5` 是针对当前车辆、轨道和作业流程编写的一组 ROS Python 脚本。它不是完整导航框架，也不是标准 Catkin 功能包集合，更接近“任务调度器 + 轨道专用控制器”。

主要文件职责：

| 文件 | 作用 |
|---|---|
| [traverse.py](../4-5/traverse.py) | 总流程调度，等待导航到位，开启视觉对轨，随后启动轨道作业 |
| [traverse.yaml](../4-5/traverse.yaml) | 轨道顺序、距离、参考坐标和 ROS 话题参数 |
| [new_copy_no_capture.py](../4-5/new_copy_no_capture.py) | 相机读取、YOLO 推理和视觉对齐循环 |
| [new_copy.py](../4-5/new_copy.py) | 轨道拟合、中线计算、像素误差滤波和 CAN 横移 |
| [Flag_4_2.py](../4-5/Flag_4_2.py) | 通过 `can0` 控制上/下轨道和换轨，并使用 FAST-LIVO 位姿闭环 |

`4-5` 代码从内容上判断属于后续项目集成或二次开发，依据包括：

- 使用 `/traverse/alignment_enabled`、`/flag1` 等轨道流程话题；
- 直接访问 SocketCAN 的 `can0`；
- 使用 YOLO 轨道分割结果计算左右轨道中线；
- 使用 `/aft_mapped_to_init` 的 FAST-LIVO 位姿；
- YAML 中包含具体轨道编号、前进距离和横移距离表；
- 引用了原 Ubuntu 机器上的 `mmLaneDet` 绝对路径。

这些内容都不是 PUTN 原始 README 所描述的功能。

## 五、两部分怎样配合

最重要的边界是：

> PUTN 负责“把车开到轨道入口附近”，`4-5` 负责“对准轨道并完成轨道内作业”。

整体数据流如下：

```text
FAST-LIVO / 其他定位模块
        │ 提供当前位置和姿态
        ▼
PUTN 导航
/cur_goal → PF-RRT* → MPC → /cmd_vel
        │
        │ 发布 /cur_global_goal_status == SUCCEEDED
        ▼
4-5/traverse.py
        │ 打开视觉对轨门控
        ▼
YOLO 识别左右轨道 → 拟合中线 → 计算像素偏差
        │
        ▼
CAN 横移对齐 → 发布 /flag1
        │
        ▼
Flag_4_2.py 使用 CAN + FAST-LIVO 完成上轨、下轨和换轨
```

它们通过 ROS 话题松耦合连接，不是 PUTN 源码直接调用 `4-5`：

- PUTN 发布导航状态；
- `traverse.py` 监听导航成功状态；
- 导航成功后，`traverse.py` 才允许 YOLO 对轨；
- 对轨成功后，轨道控制代码接管后续动作。

当前 [traverse.yaml](../4-5/traverse.yaml) 中 `wait_nav_ready_only: true`，表示 `4-5` 默认不主动完成全局规划，只等待外部 PUTN 导航系统报告到位。

## 六、两种底盘控制方式

这套工程中存在两条不同的控制链：

| 阶段 | 控制方式 | 主要代码 |
|---|---|---|
| 前往轨道入口 | ROS `/cmd_vel` 速度控制 | PUTN 的 MPC 和 controller |
| 视觉对轨、上轨、下轨、换轨 | SocketCAN `can0` 的模式/位置/速度命令 | `new_copy.py`、`Flag_4_2.py` |

因此需要避免两套控制同时向底盘发指令。现有流程通过“导航完成 → 开启对轨 → 进入轨道动作”的状态切换来划分控制权。

## 七、FAST-LIVO 在其中的位置

FAST-LIVO 不等于 PUTN，也不等于 `4-5`。它是外部定位/建图模块：

- PUTN 使用它提供的当前位置或 TF，作为路径规划与跟踪的起点；
- `Flag_4_2.py` 使用 `/aft_mapped_to_init` 位姿检查前进距离和航向；
- YOLO 仍然独立负责轨道视觉识别，两者没有在代码中进行图像级融合。

可以把三者记成：

```text
FAST-LIVO：我现在在哪里、朝向哪里
PUTN：从这里到轨道口应该怎么走
4-5：到了轨道口以后怎样对齐和完成作业
```

## 八、推荐阅读顺序

为了先理解工程流程，再深入算法，建议按下面顺序阅读：

1. 阅读本文，建立三层关系：FAST-LIVO、PUTN、`4-5`。
2. 阅读 [traverse.yaml](../4-5/traverse.yaml)，先看实际运行参数和状态话题。
3. 阅读 [traverse.py](../4-5/traverse.py)，理解导航到位后怎样切换到轨道任务。
4. 阅读 [new_copy.py](../4-5/new_copy.py)，理解 YOLO 轨道拟合和像素横移控制。
5. 阅读 [Flag_4_2.py](../4-5/Flag_4_2.py)，理解 CAN 与 FAST-LIVO 闭环。
6. 阅读 [bringup.launch](../putn_ws/src/putn-main/src/putn/putn_launch/launch/bringup.launch)，了解 PUTN 节点怎样启动。
7. 阅读 `putn_planning`，理解体素地图和 PF-RRT*。
8. 阅读 `putn_mpc`，理解局部轨迹与 `/cmd_vel` 控制。

## 九、一句话总结

PUTN 是引入的开源通用导航底座，当前工程对它做了实车适配；`4-5` 是在这个导航底座之上增加的轨道识别、CAN 对轨和轨道作业应用层。两者现在属于同一个总仓库，通过 ROS 话题衔接，但职责和控制阶段不同。
